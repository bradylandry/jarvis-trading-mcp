## High

### `get_fit_score` silently drops the `opt_type` parameter
- **File**: `friend_mcp/server.py:183`
- **Issue**: The function accepts `opt_type: str = "call"` but never passes it to the API. The call is `_api_get("/api/screener", {"tickers": ticker.upper()})` — `opt_type` is ignored. Every call to `get_fit_score(ticker, opt_type="put")` silently returns call-side data instead of put-side data. Claude will present incorrect directional analysis without any error.
- **Fix**: Pass the parameter: `_api_get("/api/screener", {"tickers": ticker.upper(), "type": opt_type})`

## Medium

### Version string mismatch (three places, all wrong)
- **File**: `friend_mcp/__init__.py:15`, `friend_mcp/server.py:333`
- **Issue**: `pyproject.toml` declares `version = "0.3.0"`, but `__init__.py` hardcodes `__version__ = "0.1.0"` and the MCP `initialize` response at `server.py:333` hardcodes `"version": "0.1.0"`. Clients that inspect `serverInfo.version` (or code that reads `friend_mcp.__version__`) will see the wrong version. Rate-limit-related changelog entries and release notes that reference 0.3.0 will be invisible to version-checking tooling.
- **Fix**: Single source of truth. In `__init__.py`, read from `importlib.metadata`:
  ```python
  from importlib.metadata import version as _pkg_version
  __version__ = _pkg_version("jarvis-trading-friend-mcp")
  ```
  In `server.py`, import and use it: `from friend_mcp import __version__`, then `"version": __version__`.

## Low

### Unguarded `int()` parse of `JARVIS_TRADING_MAX_CALLS_PER_MIN` crashes the server at startup
- **File**: `friend_mcp/server.py:68`
- **Issue**: `RATE_LIMIT_MAX_CALLS = int(os.environ.get("JARVIS_TRADING_MAX_CALLS_PER_MIN", "30"))` — if the env var is set to an empty string, a non-numeric value, or a float (`"30.5"`), `int()` raises `ValueError` at module import time. The MCP server never starts and Claude gets a generic startup failure with no useful message.
- **Fix**:
  ```python
  try:
      RATE_LIMIT_MAX_CALLS = int(os.environ.get("JARVIS_TRADING_MAX_CALLS_PER_MIN", "30"))
  except ValueError:
      RATE_LIMIT_MAX_CALLS = 30
  ```
