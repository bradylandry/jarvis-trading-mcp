## Medium

### Unguarded `int()` cast crashes server on bad env var
- **File**: `friend_mcp/server.py:68`
- **Issue**: `RATE_LIMIT_MAX_CALLS = int(os.environ.get("JARVIS_TRADING_MAX_CALLS_PER_MIN", "30"))` runs at module import time with no `try/except`. If a user sets this env var to a non-integer value (e.g., `"120calls"` or an empty string), `int()` raises `ValueError` and the MCP server crashes before it can handle any requests — including the `initialize` handshake. Claude would see a silent connection failure with no actionable error message.
- **Fix**: Wrap with a fallback:
  ```python
  try:
      RATE_LIMIT_MAX_CALLS = int(os.environ.get("JARVIS_TRADING_MAX_CALLS_PER_MIN", "30"))
  except ValueError:
      RATE_LIMIT_MAX_CALLS = 30
  ```

## Low

### Version string out of sync with `pyproject.toml`
- **File**: `friend_mcp/__init__.py:15`, `friend_mcp/server.py:334`
- **Issue**: Both files hardcode `"0.1.0"` (the initial release version). `pyproject.toml` declares version `0.3.0` and the README documents v0.3.0 features (rate limiting). This means the MCP `initialize` response advertises the wrong version to Claude Desktop / Claude Code. Not a runtime bug, but causes confusion when debugging version-specific behavior.
- **Fix**: Read version from `importlib.metadata` at startup (same pattern `audit/cli.py` uses), or at minimum update both hardcoded strings to `"0.3.0"` when cutting each release:
  ```python
  # __init__.py
  from importlib.metadata import version as _pkg_version
  __version__ = _pkg_version("jarvis-trading-friend-mcp")
  ```
  Then reference `__version__` in the `serverInfo` block in `server.py`.
