## Medium

### No expiry on cached backend token
- **File**: `friend_mcp/server.py:73`
- **Issue**: `_token_cache` is set once and never cleared. If the Azure Key Vault secret is rotated, the server silently continues using the stale token until restarted. Any tool call will return a 401 after rotation, and the only remediation is a container restart — there is no in-process recovery path.
- **Fix**: Either accept this as a known operational constraint and document the restart requirement explicitly, or add a configurable TTL (e.g., re-fetch the Key Vault secret every N minutes inside `_backend_token()`). A startup log line emitting the token's last-4 chars and fetch timestamp would make this operationally visible.

## Low

### Unvalidated enum parameters passed to backend
- **File**: `friend_mcp/server.py:146,154,164,192`
- **Issue**: `scan_universe` accepts `mode: str` and `opt_type: str` as free-form strings with only docstring-level constraints (`plan_b | plan_a | directional`, `call | put`). Invalid values propagate to the trading API and return opaque backend errors. Claude has no way to distinguish a caller typo from a genuine API failure.
- **Fix**: Add an explicit allowlist check at the top of each tool, e.g.:
  ```python
  if mode not in ("plan_b", "plan_a", "directional"):
      raise ValueError(f"mode must be plan_b | plan_a | directional, got {mode!r}")
  ```
  Same for `opt_type` in `get_thesis`, `get_fit_score`, and `get_iv`.

### 90-second HTTP timeout can stall Claude
- **File**: `friend_mcp/server.py:15`
- **Issue**: `TIMEOUT_S = 90` means a slow or hung upstream at `trading.landrycmd.com` will block Claude's tool-call execution for 90 seconds without any intermediate feedback. Claude does not display partial progress during tool execution.
- **Fix**: Consider lowering to 30–45 s for most endpoints and reserving the longer timeout only for `get_thesis` (which calls Grok). Alternatively, surface a timeout hint in the error message so callers know they can retry.

### `ALLOW_UNAUTHENTICATED=1` not logged at startup
- **File**: `friend_mcp/server.py:207`
- **Issue**: When `ALLOW_UNAUTHENTICATED=1` is set, the server starts without auth and binds to all interfaces without any warning in the startup output. This makes it easy to accidentally deploy to a public bind without noticing.
- **Fix**: Add a prominent startup warning when this override is active:
  ```python
  import warnings
  warnings.warn("ALLOW_UNAUTHENTICATED=1 set — server is running WITHOUT OAuth. Do not expose to the public internet.", stacklevel=2)
  ```
