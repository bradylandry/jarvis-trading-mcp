## High

### Backend token cache never cleared on 401
- **File:** `friend_mcp/server.py:138-139`
- **Issue:** `_api_get()` raises `RuntimeError` on a 401, but `_token_cache` is never cleared. If the Key Vault secret is rotated, every subsequent request continues hitting the cached stale token and raises `RuntimeError` without ever re-fetching from Key Vault. The process must be manually restarted to recover. The README even calls this scenario out ("if tools start returning a token error, the server-side backend token has been rotated") but the code has no self-healing path.
- **Fix:** Inside the `status_code == 401` branch, acquire `_token_lock` and set `_token_cache = None` before raising. The next request will transparently re-fetch from Key Vault.

### `get_fit_score` silently ignores the `opt_type` parameter
- **File:** `friend_mcp/server.py:164-167`
- **Issue:** The tool signature is `get_fit_score(ticker: str, opt_type: str = "call")` and the docstring promises "directional fit score … for a ticker", but `opt_type` is never forwarded to the upstream API — only `tickers` is sent. A user asking for a bearish put fit score receives the exact same response as a bullish call fit score. The tool actively misleads.
- **Fix:** Add `"type": opt_type` to the `params` dict in the `_api_get` call (assuming the `/api/screener` endpoint accepts it; verify against the upstream API contract). If the upstream doesn't accept it, remove `opt_type` from the tool signature so callers aren't misled.

### `deploy.sh` uses `$RANDOM` for ACR name — breaks on every re-run
- **File:** `deploy.sh:16`
- **Issue:** `ACR="acrjarvismcp$RANDOM"` evaluates to a different name on every execution of the script. The first deploy creates (say) `acrjarvismcp17432`. A subsequent re-deploy (e.g., to update the Container App image or auth env vars) creates `acrjarvismcp5891`, builds into it, but the Container App was never updated to pull from the new registry, so it silently continues running the old image. The old ACR instance leaks as an orphaned, billable resource.
- **Fix:** Use a fixed, deterministic name (e.g., `ACR="acrjarvismcp"` or derived from `APP`). If global uniqueness is required, compute it once and persist it (e.g., in a `.deploy-state` file or a tag on the resource group), not with `$RANDOM`.

### `deploy.sh` Key Vault policy grant parses the vault name incorrectly
- **File:** `deploy.sh:52`
- **Issue:** `az keyvault set-policy --name "${KV_URL#https://}"` strips only the `https://` prefix from `KV_URL="https://kv-jarvis-lab2.vault.azure.net/"`, leaving `kv-jarvis-lab2.vault.azure.net/` (with a trailing slash and the full FQDN). The `--name` argument expects only the vault name (`kv-jarvis-lab2`). The command fails; the `|| echo "NOTE: ..."` fallback masks the failure. The result is that the Managed Identity does not automatically receive Key Vault `get` access, and the fresh deploy will fail at token-fetch time.
- **Fix:** Extract just the vault short-name: `KV_NAME="${KV_URL#https://}"; KV_NAME="${KV_NAME%%.*}"` (yielding `kv-jarvis-lab2`), or switch to the RBAC-based `az role assignment create` which uses the full vault resource ID and is less error-prone.

## Medium

### Global rate limiter is shared across all authenticated users
- **File:** `friend_mcp/server.py:107-124`
- **Issue:** `_call_history` is a single global deque. With Entra OAuth granting per-user sessions, the 30-calls/60s ceiling is consumed collectively. One user in a runaway tool-call loop exhausts the limit for every other concurrent user.
- **Fix:** Key the rate limiter on the authenticated identity (e.g., the OAuth token subject claim that FastMCP surfaces in the request context). A `dict[str, deque]` guarded by the same lock provides per-user sliding windows.

### No input validation on user-supplied tool parameters
- **File:** `friend_mcp/server.py:146-198`
- **Issue:** `mode`, `opt_type`, and `expiration` are forwarded to the upstream API without allowlist checks. A caller can pass arbitrary string values that the server faithfully relays.
- **Fix:** Add explicit allowlist validation at the top of each tool function before calling `_api_get`. E.g.: `if mode not in ("plan_b", "plan_a", "directional"): raise ValueError(...)`. For `expiration`, validate with `re.match(r"^\d{4}-\d{2}-\d{2}$", expiration)`.

### `__init__.py` version is stale
- **File:** `friend_mcp/__init__.py:15`
- **Issue:** `__version__ = "0.1.0"` but `pyproject.toml` is at `version = "0.3.0"`. Any code that imports `friend_mcp.__version__` will report the wrong version.
- **Fix:** Derive at runtime: `from importlib.metadata import version; __version__ = version("jarvis-trading-friend-mcp")`.

## Low

### Dockerfile runs as root
- **File:** `Dockerfile:1-8`
- **Issue:** No `USER` directive — the container runs as UID 0. Container-escape exploits gain maximum privilege.
- **Fix:** Add `RUN useradd -m appuser` and `USER appuser` after the `pip install` step.

### `.env` not in `.gitignore`
- **File:** `.gitignore`
- **Issue:** A developer who creates a `.env` from `.env.example` and populates `JARVIS_TRADING_TOKEN` or `AUTH_CLIENT_SECRET` could accidentally commit it.
- **Fix:** Add `.env` (and `.env.local`) to `.gitignore`.

### `run-local.sh` is macOS-only with no diagnostic message on other platforms
- **File:** `run-local.sh:7`
- **Issue:** `security find-generic-password` is a macOS Keychain CLI. On Linux (including WSL), it fails silently with no guidance.
- **Fix:** Add a platform check: if `uname -s` is not `Darwin`, print a clear message explaining that `JARVIS_TRADING_TOKEN` must be set directly in the environment.
