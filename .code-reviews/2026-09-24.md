## Medium

### Backend token cache never expires

- **File**: `friend_mcp/server.py:65`
- **Issue**: `_token_cache` is populated once on first use and never invalidated. If the Key Vault secret (`jarvis-trading-token`) is rotated, the in-memory cache continues serving the old value until the process is restarted. In Azure Container Apps with `--min-replicas 1`, there is no automatic restart on secret rotation.
- **Fix**: Add a simple TTL (e.g., re-fetch every 24 h). Store `(_token_cache, _token_fetched_at)` and refresh when `time.monotonic() - _token_fetched_at > 86400`. Alternatively, mount the secret as an environment variable so the Container Apps platform handles rotation.

## Low

### `deploy.sh` uses `$RANDOM` for ACR name — creates a new registry on every run

- **File**: `deploy.sh:14`
- **Issue**: `ACR="acrjarvismcp$RANDOM"` embeds a shell `$RANDOM` integer that changes on every execution. A second `deploy.sh` run creates a second Azure Container Registry and rebuilds the image there, while the running app still pulls from the first one. Orphaned registries accumulate cost.
- **Fix**: Remove `$RANDOM` and use a stable, lowercase name (e.g., `ACR="acrjarvismcp"`). Run `az acr create ... || true` so the command is idempotent.

### Key Vault name extraction strips `https://` but not trailing slash

- **File**: `deploy.sh:52`
- **Issue**: `az keyvault set-policy --name "${KV_URL#https://}"` strips the `https://` prefix but leaves the trailing `/` from `https://kv-jarvis-lab2.vault.azure.net/`, resulting in `kv-jarvis-lab2.vault.azure.net/` as the vault name, which `az keyvault` will reject.
- **Fix**: Strip both: `"${KV_URL#https://}"` → `"${KV_URL#https://}"` then strip trailing slash, e.g. `KV_NAME="${KV_URL#https://}"; KV_NAME="${KV_NAME%/}"` and use `$KV_NAME`.
